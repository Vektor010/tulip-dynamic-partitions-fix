## 🔍 Детальный анализ каждого скрипта

### 1. `scripts/patch_tulip_dynamic_rom.py`
1. **Назначение:** Автоматическая замена размера Whyred `cust` (872415232 байт) на Tulip (871366656 байт) в `unsparse_super_empty.img` и `super_dummy.img` с пересчетом SHA-256.
2. **Что изменяет:** Создает новый файл `*-tulip-fixed.zip`. Исходный архив не модифицируется.
3. **Команды:** Стандартные библиотеки Python (`struct`, `hashlib`, `zipfile`, `shutil`), 7-Zip через `subprocess.run`.
4. **Права:** Обычные права пользователя в Windows/Linux.
5. **Совместимость:** Python 3.8+ на Windows, Linux, macOS.
6. **Предположения:** Ожидает структуру Google `liblp` (LpMetadata Header magic `0x414C5030` и имя раздела `cust`).
7. **Риск потери данных:** Нулевой. Исходный архив сохраняется нетронутым.
8. **Восстановление:** Исходный файл `.zip` остается оригинальным.
9. **Проверка результата:** Проверяется количество замен, наличие заголовков `liblp`, и выполняется тест архива через `zf.testzip()`.
10. **Поведение при прерывании:** Временная папка `_tulip_patch_tmp` удаляется в блоке `finally`. Если процесс прерван посредине, создаваемый выходной файл может остаться неполным.

---

### 2. `scripts/patch_tulip_dynamic_rom.ps1`
1. **Назначение:** Интерактивный запуск Python-патчера через двойной клик, командную строку или drag-and-drop.
2. **Что изменяет:** Передает аргументы в `patch_tulip_dynamic_rom.py`.
3. **Команды:** `Test-Path`, `python`.
4. **Права:** Обычные права пользователя Windows.
5. **Совместимость:** Windows PowerShell 5.1+ и PowerShell 7+.
6. **Найденные проблемы:**
   * Не проверял наличие Python в системе перед запуском.
   * При сбое Python не передавал `$LASTEXITCODE` вызывающему процессу (`exit $LASTEXITCODE`).
   * Не поддерживал `-WhatIf` / `-Confirm`.
   * Не имел параметра `-OutZip`.

---

### 3. `scripts/optimize_android17.ps1`
1. **Назначение:** Оптимизация Android 17 на аппаратах Tulip с 4 ГБ RAM (отключение неиспользуемых служб, настройка ZRAM 2.5 ГБ, mq-deadline, dex2oat speed).
2. **Что изменяет:** Состояние пакетов для user 0 (`pm uninstall -k --user 0`), глобальные настройки анимаций (`settings put`), создает `/data/adb/service.d/99-performance-tuning.sh`.
3. **Права:** Требуется подключение по ADB с правами Root (`uid=0`).
4. **Найденные проблемы:**
   * **КРИТИЧЕСКИ:** Скрипт не проверял кодовое имя подключенного устройства! При подключении любого другого телефона (Pixel, Samsung) скрипт продолжал выполнение.
   * Временный файл создавался в папке `scripts/99-performance-tuning.sh` с последующим удалением, что могло стереть отслеживаемый файл репозитория.
   * Не поддерживал `-WhatIf` (сухой прогон без внесения изменений).

---

### 4. `scripts/restore_android17.ps1`
1. **Назначение:** Полный 100% откат всех изменений, внесенных скриптом `optimize_android17.ps1`.
2. **Что изменяет:** Восстанавливает пакеты (`cmd package install-existing`), сбрасывает настройки анимаций в 1.0x, удаляет сервис из `/data/adb/service.d/`, возвращает параметры ZRAM и VM в сток.
3. **Права:** Root через ADB.
4. **Найденные проблемы:**
   * Не проверял кодовое имя устройства перед выполнением.
   * Создавал временный файл в папке проекта вместо системного `$env:TEMP`.
   * Не поддерживал `-WhatIf`.

---

### 5. `scripts/99-performance-tuning.sh`
1. **Назначение:** Применение параметров виртуальной памяти и ZRAM при каждой загрузке смартфона.
2. **Что изменяет:** `/proc/sys/vm/*`, `/sys/block/zram0/*`, `/sys/block/mmcblk0/queue/*`.
3. **Права:** Root (`/system/bin/sh` через KernelSU/Magisk `service.d`).
4. **Безопасность:**
   * Ожидает полной загрузки системы (`sys.boot_completed == 1`), что гарантирует защиту от bootloop при старте ядра.
   * Не отключает SELinux, не трогает частоты ядер процессора, не отключает термоконтроль.
