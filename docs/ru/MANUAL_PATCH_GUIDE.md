# 🛠️ Ручное исправление архива прошивки

[🇬🇧 English Version](../en/MANUAL_PATCH_GUIDE.md) | [📚 К оглавлению](README.md)

Это руководство предназначено для тех, кто **не хочет запускать готовые скрипты**, предпочитает видеть каждый байт изменений своими глазами и делать всё самостоятельно.

---

## 🧰 Что понадобится
1. Любой архиватор: **7-Zip** или **WinRAR**.
2. Бесплатный HEX-редактор: **HxD** ([официальный сайт](https://mh-nexus.de/en/hxd/)) или **ImHex**.
3. Установленный Python 3.x (только для расчёта контрольной суммы, либо микро-скрипт).

---

## 🔍 Шаг 1. Извлечение файлов метаданных
1. Откройте исходный архив прошивки (`имя_прошивки.zip`) в **7-Zip**.
2. В корне архива найдите и извлеките на рабочий стол файлы:
   * `unsparse_super_empty.img`
   * `super_dummy.img` (если присутствует в архиве).

> [!NOTE]
> Эти файлы весят всего по несколько килобайт. Они не содержат код Android — это бинарные таблицы разметки Google `liblp`.

---

## ✏️ Шаг 2. Поиск и замена байтов в HEX-редакторе

В архитектурах ARM и x86 числа хранятся в формате **Little-Endian** (младшие байты идут первыми):

| Назначение | Десятичный размер | Шестнадцатеричное число | Байт-код в файле (8 байт Little-Endian) |
| :--- | :--- | :--- | :--- |
| **Whyred (исходный)** | `872 415 232` байт | `0x34000000` | `00 00 00 34 00 00 00 00` |
| **Tulip (требуемый)** | `871 366 656` байт | `0x33F00000` | `00 00 F0 33 00 00 00 00` |

### Инструкция в HxD:
1. Откройте `unsparse_super_empty.img` в **HxD**.
2. Нажмите сочетание клавиш **Ctrl + F** (Поиск) ➔ перейдите на вкладку **Шестнадцатеричные значения**.
3. Введите строку поиска:  
   `00 00 00 34 00 00 00 00`
4. Замените найденные 8 байт на:  
   `00 00 F0 33 00 00 00 00`
5. Нажмите **F3**, чтобы проверить, есть ли ещё совпадения (в блоке описания устройства `cust`). Замените каждое вхождение.
6. Повторите ту же операцию для `super_dummy.img` (в нём число встречается 4 раза — для каждого слота метаданных).

## 🔒 Шаг 3. Пересчёт контрольных сумм SHA-256

> [!WARNING]
> Если сохранить файл сейчас, рекавери откажется его шить с ошибкой `Logical partition metadata has invalid checksum`.  
> Google защитил метаданные SHA-256 хешами заголовка и таблиц.

Чтобы не считать SHA-256 вручную в калькуляторе, воспользуйтесь открытым прозрачным кодом на Python (в нём нет сетевых вызовов или скрытых функций):

```python
import hashlib, struct

def recalculate_lpmeta_checksums(filepath):
    with open(filepath, "r+b") as f:
        raw = bytearray(f.read())

    # Поиск заголовка Google LpMetadata (магия '0PLA' = 0x414C5030)
    for pos in range(len(raw) - 4):
        if raw[pos:pos+4] == b"\x30\x50\x4c\x41":
            hdr_size = struct.unpack_from("<I", raw, pos + 8)[0]
            tbl_size = struct.unpack_from("<I", raw, pos + 44)[0]

            # 1. SHA-256 всей таблицы разделов
            tbl_hash = hashlib.sha256(raw[pos + hdr_size : pos + hdr_size + tbl_size]).digest()
            raw[pos + 48 : pos + 80] = tbl_hash

            # 2. SHA-256 заголовка с обнуленным полем собственного хеша
            raw[pos + 12 : pos + 44] = b"\x00" * 32
            hdr_hash = hashlib.sha256(raw[pos : pos + hdr_size]).digest()
            raw[pos + 12 : pos + 44] = hdr_hash

    with open(filepath, "wb") as f:
        f.write(raw)
    print(f"[OK] Контрольные суммы в {filepath} успешно обновлены!")

recalculate_lpmeta_checksums("unsparse_super_empty.img")
recalculate_lpmeta_checksums("super_dummy.img")
```

---

## 📦 Шаг 4. Упаковка файлов обратно в архив

1. Откройте исходный ZIP-архив в **7-Zip**.
2. Перетащите отредактированные файлы `unsparse_super_empty.img` и `super_dummy.img` прямо в окно архиватора с подтверждением замены.
3. Закройте 7-Zip.
4. Проверьте архив на целостность: кликните правой кнопкой мыши по ZIP ➔ **7-Zip ➔ Тестировать архив**. Ошибок быть не должно.
5. Готово! Теперь архив можно устанавливать через рекавери.
